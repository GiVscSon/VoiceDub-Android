## Что реализовано

Опциональное сохранение особенностей одного исходного голоса через MOSS на ПК. Образец 3–8 секунд собирается из разрешённого AudioPlaybackCapture; клиент отправляет образец и русский текст только при включённом флажке. Сервер загружает модель один раз, возвращает WAV. Android проигрывает его через MediaPlayer и исключает собственную озвучку из захвата; при ошибке явно переходит на обычный русский TTS. Образец/распознавание/очереди сбрасываются при смене плеера, паузе и перемотке встроенного браузера. Очереди ограничены.

Экран входа Яндекса с PKCE и callback state, как в предоставленном VOT-скрипте. Авторизация отделена от видеостраниц; токен не записывается на диск и не передаётся серверу голоса. Запрос VOT для текущего YouTube/Vimeo видео, обработка ожидания и подключение результата к синхронизации дорожки реализованы через изолированный локальный @vot.js/core 3.2.0 runtime. Доступ к двум разрешённым методам Яндекса выполняется нативно, без стороннего прокси или обхода DRM.

## Пройденные проверки

- Статическая проверка AndroidManifest/permissions/assets/workflow.
- 19 JavaScript-тестов: обнаружение видео, captions, безопасный вывод текста, pause/seek/rate/source change, drift, жест воспроизведения; отдельный тест корректного отказа VOT при недоступном транспорте.
- 12 Kotlin JUnit: playback policy, PKCE RFC vector, одноразовый callback и state, ограничение reference WAV, тишина и разрешённые адреса сервера, запрет посторонних VOT endpoints.
- 5 Python-тестов: benchmark, серверный HTTP-контракт, отбрасывание неправильного WAV/текста и 429 при перегрузке. В них используется имитация синтеза; это не доказательство качества модели.
- Настоящий MOSS ONNX runtime, два HTTP-запроса на одном экземпляре модели, reference — опубликованный пример en_2 из upstream, не запись пользователя. Ответы содержат настоящий непустой WAV.
- Pixel 2 и Pixel C, Android 15/API 35: по 3 instrumented tests, 0 failures, 0 errors, 0 skipped. Проверены запуск/переключение ориентации, отсутствие автоматического включения отправки образца, HTTP-клиент и фактическое завершение MediaPlayer, загрузка локального VOT bundle. Android HTTP test использует фиксированный WAV, полученный реальной моделью; саму модель эмулятор не запускает.

## Измерения настоящего сервера

Загрузка модели: 9.393 секунды. Первый HTTP-запрос: 10.842 секунды на 4.72 секунды аудио (RTF 2.297); второй — 11.789 секунды на 5.76 секунды (RTF 2.047). WAV stereo 48 kHz. Это измерения на CPU GitHub runner, а не на ПК пользователя. Скорость медленнее реального времени, поэтому накопление задержки и отбрасывание старых ожидающих фраз ожидаемы.

## Что не подтверждено

Живой вход в Яндекс с пользовательским аккаунтом и выдача дорожки VOT. Пробный прямой анонимный запрос из среды разработки завершился ошибкой, причина не установлена. Нельзя объявлять VOT работающим по успешной загрузке JS и сборке.

Полная новая цепочка AudioPlaybackCapture → Vosk → ML Kit → MOSS на POCO/физическом планшете. Работа предыдущей 0.4 подтверждена пользователем, но это не заменяет проверку preview. Сходство голоса, произношение, несколько говорящих, музыкальный фон, губная синхронизация, поведение в фоне и новая пауза/перемотка на реальном видео не оценены. Сервер проверен на Linux; Windows PowerShell bootstrap в Windows не запускался. Автономного MOSS на телефоне нет.

## Первый запуск

Для обычного перевода скачайте языковую модель в preview и используйте прежний захват. Для сохранения голоса распакуйте комплект ПК, следуйте companion/README-RU.md, в общей Wi-Fi сети укажите IP и порт ПК, проверьте сервер и включите соответствующий флажок. Лучше начать с одного говорящего без музыки. Не запускайте одновременно перевод в обеих версиях приложения.

Для VOT войдите через новый экран Яндекса, откройте YouTube/Vimeo во встроенном браузере, нажмите «Перевести видео · Яндекс VOT». Только если сервис вернёт дорожку, приложение предложит включить звук кнопкой внутри страницы. Перед проверкой не требуется вводить Yandex Cloud API-ключ.
